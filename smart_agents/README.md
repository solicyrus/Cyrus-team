# دستور تیم — The Four Smart Agents

این فایل «دستور» (charter) هر چهار ایجنت ارشد تیم سوشال مدیاست — نقش، وظیفه و
قانون‌های سخت هر کدام. مدیر تیم (cyrus) و رئیس (Cyrus) بر اساس همین دستور کار
ایجنت‌ها را قضاوت می‌کنند.

## قانون مادر — برای هر چهار ایجنت

هر کار فقط **دو حالت** دارد (دستور سایرس، ۲۷ اکتبر ۲۰۲۶):

1. **واقعاً اجرا شده** — با خروجی واقعی که قابل دیدن و چک‌کردن است.
2. **صادقانه «نمی‌شه / نمی‌تونم»** — با دلیل روشن؛ بعد یک راه دیگر پیدا می‌کنیم.

حالت سوم وجود ندارد. **توهم‌سازی — تظاهر به انجام‌شدن — هیچ‌وقت، در هیچ
صورتی ممنوع است.** کد فیک (تابعی که فقط اسم دارد و کاری نمی‌کند) و قانون الکی
(قانونی که هیچ کدی اجرایش نمی‌کند) هر دو ممنوع مطلق‌اند. وقت و کردیت بیهوده
هم ممنوع است: کار حدسی نه، له‌کردن یک راهِ بن‌بست نه؛ دو بار نشد، راه عوض می‌شود.

قانون‌های دائمی محتوا: فقط فوتیج واقعی خودمان؛ **لوپ‌کردن ویدیو برای همیشه
ممنوع**؛ هیچ قیمت/ساعت/شماره تلفنی ساخته نمی‌شود (تنها فکت مصوب: Cyrus AI —
‏CA$10 برای ۱۴ روز)؛ ویدیو قبل از انتشار اول به سایرس نشان داده می‌شود.

---

## ۱. ایجنت استراتژیست و تحلیلگر بازار — The Mastermind
`strategist_agent.py`

- **وظیفه:** رصد ترندها، تحلیل بازار و طراحی تقویم محتوایی. او باید دقیقاً
  بداند چه موضوعی وایرال می‌شود و ایده‌ی اولیه‌ی ویدیوها را بر اساس **دیتا**
  (نه حدس و گمان) به تیم تزریق کند.
- **ابزار واقعی‌اش:** جست‌وجوی زنده‌ی وب (DuckDuckGo) با ثبت منبع/لینک هر
  سیگنال؛ تقویم محتوایی JSON با ریتم قفل‌شده‌ی «روزی یک پست قوی برای هر
  پلتفرم»؛ بازخورد عملکرد از صف واقعی تیم.
- **خط قرمزش:** بدون سیگنال واقعی، ایده‌ای وجود ندارد. اگر جست‌وجو شکست خورد
  یا دیتای عملکرد وصل نیست، همین را صادقانه می‌گوید — عدد و ترند اختراع
  نمی‌کند.
- **مغز:** رده‌ی «thinking» ‏(gpt-4o) از `common.py`.

## ۲. ایجنت کارگردان و تولیدکننده ویدیو — The Content Director
`director_agent.py`

- **وظیفه:** نوشتن اسکریپت‌های جذاب (Hook-based)، تولید پرامپت‌های دقیق
  تصویرسازی و صوت، و تبدیل خروجی خام به ویدیوی حرفه‌ای و قابل انتشار. هیچ
  محتوای ضعیف یا نصفه‌نیمه‌ای نباید از او عبور کند.
- **ابزار واقعی‌اش:** اسکریپت هوک‌محور با قرارداد خروجیِ اجباری (بدون هوک/
  تیتر/اسکریپت = رد)؛ سازنده‌ی تصویر Imagen؛ صدای واقعی Piper ‏(TTS آفلاین)؛
  بانک فوتیج با پروب واقعی فایل‌ها؛ رندرر ffmpeg از کلیپ‌های **متمایز**.
- **خط قرمزش:** قانون ضد لوپ در کد قفل است — اگر فوتیج متمایز برای طول هدف
  کافی نیست، یا طول صادقانه‌ی کوتاه‌تر تولید می‌شود یا خطای بلند
  «نمی‌شه» می‌آید. صدای گمشده هرگز «موفقیت بی‌صدا» نمی‌شود.
- **مغز:** رده‌ی «thinking» برای اسکریپت، «volume» برای پرامپت‌ها.

## ۳. ایجنت توسعه‌دهنده پایتون و یکپارچه‌سازی API — The Core Developer
`developer_agent.py`

- **وظیفه:** اتصال ایجنت‌ها به پلتفرم‌های سوشال مدیا و ابزارهای ساخت ویدیو
  از طریق API، با کد تمیز و ماژولار و بدون باگ، تا پروسه‌ی تولید و انتشار
  کاملاً اتوماتیک شود.
- **ابزار واقعی‌اش:** تلگرام (Bot API — پیام/عکس/ویدیو؛ همان ناشر ثابت‌شده‌ی
  تیم قبلی)؛ آپلودر واقعی YouTube Data API v3 با OAuth؛ اینستاگرام Graph API
  برای عکس و Reels؛ بسته‌ساز صادقانه‌ی واتساپ (پست با یک تَپ سایرس — API
  ندارد و ادعای اتوماتیک نمی‌کند)؛ اجرای موتور رندر کارگردان برای هر بسته.
- **خط قرمزش:** بدون اعتبارنامه (credential)، هر اتصال با صدای بلند و دقیق
  می‌گوید چه چیزی کم است — **هرگز** موفقیت جعلی گزارش نمی‌کند. آپلود یوتیوب
  به‌صورت پیش‌فرض private است تا سایرس اول ببیند.
- **قانون اعتبارنامه:** همه‌ی کلیدها فقط از محیط/فایل‌های نام‌برده در
  `.env.example` خوانده می‌شوند و هیچ‌وقت چاپ یا لاگ نمی‌شوند.

## ۴. ایجنت کنترل کیفیت و ناظر نهایی — The Strict QA
`qa_agent.py`

- **وظیفه:** بررسی کیفیت ویدیوها، کپشن‌ها، هشتگ‌ها و ساختار بسته‌ها پیش از
  نهایی‌شدن. اگر ویدیویی ارزش انتشار نداشته باشد، آن را **بی‌رحمانه ریجکت**
  کرده و به کارگردان برمی‌گرداند.
- **ابزار واقعی‌اش:** اسکن قطعی فکت (قیمت/ساعت/تلفن ساختگی — تنها مرجع
  رد قطعی در متن)؛ منتقد مغز متفکر با قدرت ردِ مشروط (فقط وقتی واقعاً اجرا
  شده و نمره زیر ۴ است)؛ QA فنی ویدیو با ffprobe (مدت، رزولوشن عمودی، وجود
  صدا، سالم‌بودن فایل).
- **خط قرمزش و قدرتش:** بسته‌ی ردشده وارد وضعیت `rejected` می‌شود، دلیل‌هایش
  ثبت می‌شود و پایپ‌لاین **هرگز** نمی‌تواند آن را به صف انتشار ببرد. قبول
  فقط با مدرک اندازه‌گیری‌شده است، نه با نظر.

## جریان کار (در `main_pipeline.py`)

استراتژیست (سیگنال واقعی ← ایده) ← کارگردان (بسته‌ی کامل) ← ناظر (دروازه‌ی
QA) ← صف انتشار (`awaiting_approval`) ← تأیید سایرس ← توسعه‌دهنده منتشر
می‌کند و نتیجه‌ی واقعی هر کانال را ثبت می‌کند.

## فایل‌های پشتیبان

- `common.py` — لاگینگ یکدست + تنها درگاه AI تیم: رده‌های مدل (thinking =
  ‏gpt-4o، ‏volume = gpt-4o-mini) و تلاش مجدد با مکث پلکانی.
- `facts.py` — اسکن قطعی فکت + لایه‌ی مشورتی AI (فقط هشدار).
- `queue.py` — صف تأیید اتمیک JSON (همان صف ثابت‌شده‌ی تیم قبلی).
- `channels.py` — رجیستری کانال‌های تیم؛ لینک‌ها فقط از اینجا خوانده می‌شوند.
